# RelayRoom

A temporary, server-relayed room for sharing files, links, text, photos, and voice notes between browsers.

## Learning Mode

This project is being built partly for learning.

Whenever you make a meaningful implementation change:

1. Explain what you changed in plain English.
2. Explain why this approach was chosen over the obvious alternatives.
3. Identify any new concept, API, library, pattern, or .NET feature introduced.
4. Explain the concept briefly enough that I could discuss it in an interview.
5. Point out any important trade-offs, failure modes, or security concerns.
6. Link to the most relevant official documentation where possible.
7. Add concise notes to `/docs/learning-notes.md`.

Do not fill the notes with trivial changes such as renaming variables or formatting.

For non-trivial features, also include:

- "What I should understand before moving on"
- "Questions I should be able to answer"
- "Things worth experimenting with manually"

Prefer official Microsoft/.NET, PostgreSQL, Azure, React, MDN, and protocol documentation over random blog posts.

Never hide complexity. If generated code uses a concept I may not understand, explain it before treating the task as finished.

After completing implementation:

- Build and test it
- Explain the important implementation decisions
- Teach any new concepts introduced
- Say what code I should personally inspect
- Give 3-5 questions I should be able to answer about this feature
- Provide links to relevant official documentation
- Update `docs/learning-notes.md`
- Update `docs/interview-notes.md` only if the change adds interview-relevant knowledge

Keep learning notes concise and useful; do not document trivial edits.

## Interesting bugs

Do not immediately fix difficult bugs. First explain what is failing, point toward the relevant code, and give a chance to reason about it. If asked to fix it, proceed.

Syntax errors and obvious typos may be fixed immediately.
